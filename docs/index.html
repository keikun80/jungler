Jungle Tools 종합 사용자 매뉴얼

다중 AWS 계정 환경에서 VPC 보안 그룹 제어, S3 Object Lock 불변 감사 로깅, EBS/EFS/RDS 백업 통합 관제 및 Slack/Email 알림 자동화를 제공하는 엔터프라이즈 클라우드 관리 콘솔 매뉴얼입니다.

1. 시스템 아키텍처 및 보안 개요

Jungle Tools는 허브(Hub) 계정과 멀티 스포크(Spoke) 계정(총 10개 계정)을 효율적이고 안전하게 제어하기 위해 BFF(Backend-for-Frontend) 세션 쿠키 인증 모델 및 서버리스 클라우드 아키텍처를 채택하였습니다.

BFF HttpOnly 세션 쿠키 아키텍처 브라우저에 AWS 평문 자격 증명을 저장하지 않고, AWS STS 검증 후 발급되는 HttpOnly; Secure; SameSite=None 세션 쿠키(8시간 TTL)를 통해 모든 API 요청을 안전하게 인가합니다.

주요 구성 컴포넌트

  • 프론트엔드 (S3 Static Website Hosting): 별도의 무거운 프레임워크 없이 가볍고 빠른 반응형 웹 콘솔.
  • API Gateway v2 (HTTP API): Lambda Request Authorizer를 통해 비인가 요청을 게이트웨이 레벨에서 401 차단.
  • BFF Handlers & Business Lambdas: STS 검증, 보안 그룹 CRUD, 백업 스캐너, 알림 발송 엔진.
  • DynamoDB (UserSessionsTable & SgAuditLogs): 256비트 세션 토큰 저장 및 실시간 감사 로그 인덱싱.
  • S3 Object Lock Bucket (WORM): GOVERNANCE 모드로 30일간 변조 및 삭제가 불가능한 불변 감사 로그 저장소.

2. 공통 레이아웃 및 글로벌 UI 요소

콘솔의 좌측 사이드바와 상단 헤더 바는 언제 어디서나 대상 계정을 변경하고 실시간 상태를 파악할 수 있도록 고정 배치되어 있습니다.

Jungle Tools 글로벌 레이아웃 (좌측 사이드바 계정 셀렉터 + 상단 브레드크럼)
UI 영역 주요 요소 기능 및 동작 설명
사이드바 상단 Brand & Badge Jungle Tools 브랜드 로고 및 개발 브랜치/커밋 해시 표시 (예: develop@da31885).
사이드바 계정 카드 Target Account Home 바로 아래 위치하며, Hub (l-iam-s2), l-ellotte-dev 등 관리할 대상 AWS 계정을 즉시 전환.
사이드바 하단 Footer Info 현재 연결된 백엔드 API Endpoint URL 및 위임 역할 Role Name 출력.
상단 바 좌측 Breadcrumb 현재 페이지의 계층형 위치를 Home, SG Manage / Dashboard 등으로 동적 표시.
상단 바 우측 API Status Badge Online(녹색), Expired(주황색), Disconnected(회색)으로 연결 상태 실시간 표시.
상단 바 우측 Session Info & Logout 로그인된 IAM User 식별자 표시 및 세션 만료 시 다시 로그인, 수동 종료 Disconnect 버튼 제공.

3.1 홈 대시보드 (Home)

전체 클라우드 인프라의 헬스 상태, 보안 그룹 규칙 수, 멀티 계정 백업 준수율을 종합 집계하여 보여주는 메인 화면입니다.

화면 주요 구성 요소

  • 메트릭스 카드 그리드: 활성 VPC 수, 보안 그룹 수, 등록된 인바운드/아웃바운드 규칙 총계, 보호 중인 백업 리소스 수.
  • 퀵 점프(Quick Jump) 배너: SG 대시보드, 백업 대시보드, 슬랙 웹훅 설정, 이메일 수신자 등록, 감사 로그로 즉시 이동하는 바로가기 카드.
  • 멀티 계정 백업 현황판: 10개 AWS 계정의 리소스 보호 현황과 마지막 스캔 시각을 실시간 테이블로 제공.

3.2 보안 그룹 관리 (SG Manage > Dashboard)

계정 내 모든 VPC와 보안 그룹을 탐색하고, 인바운드/아웃바운드 방화벽 규칙을 웹상에서 간편하게 등록, 수정, 삭제하는 화면입니다.

SG Manage 대시보드 (VPC 아코디언 목록 + 인바운드/아웃바운드 룰 편집기)

주요 기능 및 화면 요소

  1. + New Security Group: 신규 보안 그룹 생성 팝업 모달을 호출합니다.
  2. VPC Accordion: VPC별로 그룹화된 보안 그룹 목록을 아코디언 형태로 펼치거나 접을 수 있습니다.
  3. Rule Editor Tabs: 인바운드(Inbound) 및 아웃바운드(Outbound) 규칙 테이블 탭 전환.
  4. Rule Table Columns: Type(HTTPS, SSH, Custom), Protocol(TCP, UDP), Port Range, Source/Destination CIDR, Description.
  5. + Add Rule & Save Changes: 새로운 방화벽 규칙 행을 추가하고, 수정된 규칙을 AWS EC2에 즉시 일괄 커밋합니다.

3.3 보안 그룹 감사 로그 (SG Manage > Logs)

보안 그룹의 모든 생성(CREATE), 규칙 변경(UPDATE), 삭제(DELETE) 이력을 조회하고, WORM S3 Object Lock 불변 저장소와 대조 검증하는 컴플라이언스 화면입니다.

SG Audit Logs 화면 (WORM Object Lock GOVERNANCE 모드 뱃지 + JSON Diff 상세 모달)
WORM (Write Once Read Many) 컴플라이언스 준수 모든 감사 로그는 DynamoDB뿐만 아니라 S3 Object Lock 버킷에 암호화되어 아카이빙되며, 보존 기간(30일) 동안 AWS 루트 계정을 포함한 누구도 로그를 수정하거나 삭제할 수 없습니다.

필터 및 상세 보기 기능

  • Action 필터: CREATE, UPDATE, DELETE 작업 유형별 필터링.
  • SG ID 검색: 특정 보안 그룹 ID(sg-xxxx)에 대한 이력만 정밀 검색.
  • View JSON 버튼: 변경 전/후 규칙 차이점(Diff), 클라이언트 IP, 사용자 IAM ARN을 포맷팅된 JSON으로 즉시 열람.

3.4 멀티 백업 통합 관제 (Backup Monitor > Dashboard)

EBS 볼륨, EFS 파일 시스템, RDS 데이터베이스의 백업 상태를 실시간 스캔하여 스냅샷 보유 여부 및 준수율을 판별합니다.

백업 상태 (Status) 판별 기준 (Criteria) UI 표기
Healthy (정상) 최근 7일 이내 성공적으로 생성된 유효 스냅샷 존재 PROTECTED
Failure (실패/경고) 스냅샷 생성이 실패했거나 8일 이상 경과된 오래된 백업만 존재 WARNING
Unprotected (미보호) 백업 정책이 비활성화되었거나 스냅샷이 전혀 존재하지 않음 UNPROTECTED

3.5 Slack 웹훅 설정 (Notification > Slack > 웹훅)

다양한 업무 채널(DevOps, 보안, 관제팀)로 일일 백업 보고서를 전송하기 위해 다중 Slack Incoming Webhook을 관리합니다.

Slack Webhooks Management (다중 웹훅 카드 목록 + 신규 웹훅 등록 모달)

웹훅 등록 및 제어 가이드

  • + Add Webhook: 신규 슬랙 웹훅 등록 팝업 호출.
  • Webhook URL 검증: hooks.slack.com/services/..., /workflows/... 정규식 화이트리스트 자동 검증 (SSRF 원천 차단).
  • Message Type: detailed (Block Kit 기반 리치 테이블 리포트) / simple (컴팩트 텍스트 요약).
  • Schedule: 매시간(Hourly), 매일 오전 9시(Daily 9AM), 또는 사용자 정의 Custom Cron 표현식.
  • Test All Webhooks: 활성화된 모든 Slack 채널로 테스트 메시지 동시 발송.

3.6 이메일 알림 설정 (Notification > Email)

AWS SES 또는 사내 SMTP 메일 서버를 연동하고, 보고서를 수신할 담당자 이메일 목록을 관리합니다.

1) SMTP 메일 서버 설정 (`Notification > Email > SMTP`)

SMTP Host, Port(587/465), SSL/TLS 보안 연결, 인증 계정을 설정하고 실시간 핸드셰이크 테스트를 수행합니다.

2) 주소 등록 & 실시간 리포트 미리보기 (`Notification > Email > 주소 등록`)

  • 다중 수신자 등록: 쉼표(,), 세미콜론(;), 줄바꿈으로 구분된 이메일 목록 일괄 등록 (RFC 5322 표준 유효성 검증).
  • 일일 리포트 미리보기 (`Preview Report`): 발송될 실시간 HTML 백업 리포트를 화면에서 직접 확인.
  • 즉시 발송 (`Send Now`): 등록된 모든 수신자에게 백업 현황 종합 보고서 즉시 전송.

4. 주요 운영 시나리오 가이드

시나리오 1: 신규 보안 그룹 생성 및 인바운드 방화벽 규칙 적용

  1. 좌측 사이드바에서 대상 계정(예: l-ellotte-dev)을 선택합니다.
  2. 사이드바에서 SG Manage > Dashboard 메뉴로 이동합니다.
  3. 상단의 + New Security Group 버튼을 클릭하고 이름, 설명, 소속 VPC를 선택하여 생성합니다.
  4. 생성된 보안 그룹을 클릭한 후 + Add Rule을 눌러 포트(예: 443)와 Source CIDR(0.0.0.0/0)을 입력합니다.
  5. Save Changes를 클릭하여 EC2에 즉시 반영합니다.

시나리오 2: 감사 로그 확인 및 불변성 검증

  1. 사이드바에서 SG Manage > Logs 메뉴로 이동합니다.
  2. 방금 수행된 CREATE 및 UPDATE 작업 로그를 확인합니다.
  3. View JSON을 클릭하여 변경된 규칙의 Diff와 S3 WORM 경로(s3://...)를 확인합니다.

5. 자주 묻는 질문 (FAQ) & 트러블슈팅

Q1. 로그인 시 "Failed to fetch" 오류가 발생합니다.

API Gateway의 CORS 정책에 Access-Control-Allow-Credentials: true가 활성화되어 있어야 하며 프론트엔드 호스팅 도메인이 등록되어 있어야 합니다 (최신 배포에 적용 완료). 브라우저 캐시를 강력 새로고침(Ctrl + F5)해 주세요.

Q2. 8시간 후 세션이 만료되었다는 알림이 나타납니다.

보안 강화를 위한 8시간 TTL 세션 만료 정책입니다. 상단 헤더 바의 다시 로그인 버튼을 클릭하여 자격 증명을 입력하면 작업 상태를 유지한 채 세션이 갱신됩니다.

Q3. 특정 스포크 계정의 리소스를 조회할 수 없습니다.

해당 스포크 계정에 JungleToolsCrossAccountRole IAM 역할이 생성되어 있는지 확인하세요. 스포크 계정에서 spoke-account-template.yaml을 배포하면 해결됩니다.
