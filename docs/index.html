2. SG Manage (보안 그룹 대시보드)

계정 내 VPC별 아코디언 목록을 확인하고, 보안 그룹 생성 및 인바운드/아웃바운드 방화벽 규칙을 웹에서 즉시 추가, 수정, 삭제하는 화면입니다.

영역 UI 요소 설명
상단 액션 #btn-open-create-sg + New Security Group 버튼: 신규 보안 그룹 생성 모달(#modal-create-sg) 호출.
상단 액션 #btn-refresh-sgs Refresh 버튼: AWS EC2 API를 호출하여 최신 VPC 및 보안 그룹 목록 갱신.
VPC 탐색 #sidebar-sg-search 보안 그룹 이름 또는 ID를 실시간 필터링하는 검색 입력창.
VPC 탐색 #vpc-list VPC별 아코디언 목록 컨테이너. VPC 클릭 시 내부 보안 그룹 카드가 펼쳐짐.
규칙 탭 #tab-inbound / #tab-outbound 인바운드 규칙 / 아웃바운드 규칙 탭 전환 (규칙 개수 뱃지 표시).
규칙 편집 #btn-add-inbound-rule + Add Rule 버튼: 새 방화벽 규칙(Type, Port, CIDR, Description) 행 추가.
규칙 저장 #btn-save-rules Save Changes 버튼: 편집된 방화벽 규칙을 EC2에 즉시 일괄 반영하고 감사 로그 기록.
보안그룹 삭제 #btn-delete-sg 선택된 보안 그룹을 안전하게 삭제 (확인 팝업 후 실행).

3. SG Logs (보안 감사 로그 & WORM 검증)

보안 그룹의 CREATE, UPDATE, DELETE 변경 이력을 조회하며, S3 Object Lock 불변 저장소에 저장된 위치(s3Location)를 확인할 수 있습니다.

UI 요소 표시 이름 / 식별자 기능 및 규정 준수 설명
#log-s3-bucket-name WORM S3 Bucket Name 감사 로그 원본이 저장되는 암호화 전용 S3 버킷 명칭 표시.
Object Lock Badge GOVERNANCE Mode (30 Days) S3 Object Lock 보존 모드가 활성화되어 있어 30일간 삭제/변조 불가함을 인증.
#btn-refresh-logs Refresh Logs 버튼 최신 감사 로그 목록을 DynamoDB로부터 실시간 다시 조회.
#modal-log-detail JSON Detail Modal 로그 행의 View Details 클릭 시 이전/이후 규칙 차이점(JSON Diff) 열람.

4. Backup Monitor (멀티 서비스 백업 관제)

EBS 볼륨, EFS 파일 시스템, RDS 데이터베이스의 백업 상태를 판별하는 3대 서비스 탭을 제공합니다.

서비스 탭 식별자 스캔 대상 리소스 및 상태 판별
EBS 스냅샷 #tab-backup-ebs EBS 볼륨 목록, 볼륨 크기, 최근 7일 이내 생성된 EBS 스냅샷 유무 판별.
EFS 파일 시스템 #tab-backup-efs EFS 파일 시스템, 자동 백업 정책(ENABLED/DISABLED), 복구 시점(Recovery Point) 확인.
RDS 데이터베이스 #tab-backup-rds RDS 인스턴스, DB 엔진, 수동/자동 스냅샷 현황 및 최신 복구 시점 점검.

5. Slack 웹훅 설정 (Notification > Slack > 웹훅)

다양한 Slack 채널로 일일 백업 보고서를 자동 발송하기 위해 N개의 Incoming Webhook을 관리합니다.

UI 요소 식별자 기능 설명
#btn-open-add-webhook + Add Webhook 버튼 웹훅 이름, URL, 메시지 포맷, 스케줄을 설정하는 신규 등록 모달(#modal-webhook) 호출.
#btn-test-all-webhooks Test All Webhooks 버튼 등록되어 활성화된 모든 Slack 웹훅으로 테스트 메시지 일괄 발송.
#webhook-modal-url Webhook URL 입력 https://hooks.slack.com/services/... 또는 /workflows/... 형식만 허용 (SSRF 검증).
#webhook-modal-msgtype Message Type 선택 detailed (Block Kit 상세 테이블) 또는 simple (컴팩트 텍스트 요약).

8. Email 주소 등록 (Notification > Email > 주소 등록)

일일 백업 리포트를 수신할 담당자 이메일 목록을 관리하고, HTML 이메일 리포트를 화면에서 미리보기 및 즉시 발송합니다.

UI 요소 식별자 기능 설명
#email-recipients-input 수신자 목록 텍스트 영역 쉼표(,), 세미콜론(;), 줄바꿈으로 구분된 다중 이메일 입력 (RFC 5322 검증).
#btn-save-recipients Save Recipients 버튼 검증된 이메일 수신자 목록을 DynamoDB SlackConfig 테이블에 저장.
#btn-preview-email-report Preview Report 버튼 현재 시점의 10개 AWS 계정 백업 현황을 집계한 실제 HTML 이메일 리포트를 화면에 렌더링.
#btn-send-email-now Send Email Now 버튼 등록된 모든 수신자에게 백업 현황 리포트 즉시 전송.

자주 묻는 질문 (FAQ) & 트러블슈팅

Q1. 로그인 시 "Failed to fetch" 오류가 발생합니다. API Gateway CORS 정책에 Access-Control-Allow-Credentials: true가 누락되었거나 브라우저 캐시 문제일 수 있습니다. 브라우저에서 Ctrl + F5(강력 새로고침)를 눌러 최신 스크립트를 로드해 주세요.
Q2. 8시간 후 화면을 클릭하니 "세션이 만료되었습니다" 알림이 발생합니다. BFF 보안 정책에 따라 발급된 HttpOnly 세션 쿠키는 8시간 TTL을 가집니다. 상단 헤더의 다시 로그인 버튼을 클릭하여 자격 증명을 입력하면 작업 상태를 유지한 채 세션이 갱신됩니다.
Q3. 특정 스포크 계정(예: l-ellotte-dev) 선택 시 보안 그룹 조회가 되지 않습니다. 해당 스포크 계정에 JungleToolsCrossAccountRole IAM 역할이 생성되어 있는지 확인하세요. 스포크 계정에서 spoke-account-template.yaml 템플릿을 배포하면 해결됩니다.
