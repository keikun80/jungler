Jungle Tools 사용자 매뉴얼 & 사용법

실제 Jungle Tools 콘솔 화면 캡처와 함께 각 기능의 상세 사용 절차(Step-by-Step), UI 구성 요소 및 운영 노하우를 안내합니다.

0. 로그인 및 BFF 세션 인증

Jungle Tools는 BFF(Backend for Frontend) 패턴의 보안 아키텍처를 적용하여 클라이언트에 민감한 장기 AWS 자격 증명을 노출하지 않고 안전한 HttpOnly 세션 쿠키로 통신합니다.

화면 캡처: Jungle Tools 로그인 모달 (#modal-login) BFF Authentication
로그인 성공 시 8시간 동안 유효한 암호화 HttpOnly 세션 쿠키가 발급되며 자동으로 전체 서비스 API가 활성화됩니다.

로그인 및 세션 관리 사용법 (How-To)

1
콘솔 접속 및 로그인 팝업 확인
Jungle Tools 웹 URL에 접속하면 초기 인증 상태를 검사합니다. 비인가 상태인 경우 #modal-login 인증 창이 화면 중앙에 나타납니다.
2
관리자 자격 증명 입력
Admin ID 및 Password를 입력란에 기입합니다.
💡 초기 관리자 계정은 시스템 관리자가 발급한 계정(기본: admin)을 사용합니다.
3
로그인 실행 및 세션 연결 확인
Sign In 버튼을 클릭합니다. 인증이 완료되면 모달이 닫히며 상단 헤더 바에 Online 녹색 뱃지와 작업자 정보(IAM/User)가 표시됩니다.
4
세션 종료 (로그아웃)
작업을 마친 후 상단 헤더 바 우측의 Disconnect 버튼을 클릭하면 세션 쿠키가 파기되고 즉시 로그아웃됩니다.

사이드바 & 대상 AWS 계정 전환 (Target Account)

좌측 사이드바 상단의 Target Account 선택기를 통해 여러 AWS 계정의 리소스를 원클릭으로 넘나들며 중앙 집중 관리할 수 있습니다.

대상 계정 전환 방법 (How-To)

1
Target Account 드롭다운 클릭
좌측 사이드바의 Target Account 드롭다운 박스를 클릭합니다.
2
관리 대상 계정 선택
목록에서 관리할 계정을 선택합니다:
• Hub (l-iam-s2): 마스터 허브 관리 계정
• l-ellotte-dev: 개발 스포크 계정 1
• l-b2-dev: 개발 스포크 계정 2
• l-cicd-s2: CI/CD 파이프라인 전용 계정
3
자동 AssumeRole 및 데이터 갱신 확인
선택 즉시 백엔드에서 JungleToolsCrossAccountRole 역할을 통해 STS 임시 자격 증명을 획득하고, 현재 화면(보안그룹 목록, 백업 현황 등)이 해당 계정의 실제 리소스로 자동 갱신됩니다.

1. Home (통합 인프라 & 보안 대시보드)

Jungle Tools 진입 시 나타나는 최상단 통합 관제 화면으로, 보안 그룹 지표, 백업 관제 지표 및 주요 기능 바로가기를 한눈에 제공합니다.

화면 캡처: Home 통합 관제 대시보드 (#view-home) Overview
계정 내 전체 VPC 수, 보안 그룹 수, 인바운드 룰 총합 및 EBS/EFS/RDS 백업 보호율을 실시간 집계합니다.

Home 대시보드 활용법 (How-To)

1
실시간 지표 갱신
우측 상단의 Refresh Metrics 버튼을 클릭하여 전체 VPC 및 백업 스토리지의 최신 상태를 실시간으로 재집계합니다.
2
보안 그룹 현황 파악 및 바로가기
Active VPCs, Total Security Groups, Inbound Rules 카드를 확인하고, 우측 보안 그룹 관리 바로가기 → 버튼을 눌러 SG Manage 화면으로 즉시 이동합니다.
3
백업 건전성(Health) 점검
Healthy (<=7d) 지표가 총 리소스와 일치하는지 확인합니다. 만약 Failure/Warning 또는 Unprotected 수치가 존재할 경우 백업 관제 바로가기 →를 눌러 상세 원인을 분석합니다.

2. SG Manage (보안 그룹 및 방화벽 관리)

계정 내 VPC별 아코디언 목록을 확인하고, 신규 보안 그룹 생성 및 인바운드/아웃바운드 방화벽 규칙을 웹에서 직관적으로 추가·수정·삭제합니다.

화면 캡처: SG Manage 방화벽 룰 편집기 (#view-sg-dashboard) Firewall Management
VPC별 보안 그룹을 선택하고 인바운드/아웃바운드 룰을 테이블에서 직접 편집한 뒤 즉시 적용할 수 있습니다.

보안 그룹 생성 및 방화벽 규칙 편집 사용법 (How-To)

1
신규 보안 그룹 생성 (+ New Security Group)
1. 상단 우측 + New Security Group 버튼을 클릭합니다.
2. 모달 창에서 대상 VPC를 선택하고, Group Name과 Description을 입력합니다.
3. Create Security Group 버튼을 클릭하여 즉시 생성합니다.
2
보안 그룹 선택 및 규칙 탭 전환
좌측 VPC 아코디언 트리에서 대상 보안 그룹(예: web-sg)을 클릭합니다. 우측 편집기에서 Inbound Rules 또는 Outbound Rules 탭을 선택합니다.
3
규칙 추가 및 수정 (+ Add Rule)
1. + Add Rule 버튼을 클릭하여 새 규칙 행을 추가합니다.
2. Type(HTTP, HTTPS, SSH, Custom TCP 등), Port Range(예: 443, 8080), Source CIDR(예: 10.0.0.0/16 또는 0.0.0.0/0), Description을 설정합니다.
3. 불필요한 규칙은 우측의 🗑 삭제 아이콘을 눌러 제거합니다.
4
변경 사항 저장 (Save Changes)
우측 하단의 Save Changes 버튼을 클릭합니다. 백엔드에서 AWS EC2 Authorize/RevokeSecurityGroupIngress API를 호출하여 즉시 반영하며, 모든 변경 내역은 감사 로그에 안전하게 기록됩니다.

3. SG Logs (보안 감사 로그 & WORM 스토리지 검증)

모든 보안 그룹 생성, 수정, 삭제 이력을 조회하며, S3 Object Lock (WORM 불변 스토리지)에 암호화 저장된 감사 원본 파일의 무결성을 검증합니다.

화면 캡처: SG Logs 보안 감사 로그 및 WORM 불변 스토리지 (#view-sg-logs) Compliance & Audit
감사 로그는 DynamoDB와 더불어 30일간 삭제/변조가 원천 차단되는 S3 Object Lock 버킷에 동시 보관됩니다.

보안 감사 로그 조회 및 검증 사용법 (How-To)

1
WORM 스토리지 및 보존 규정 확인
화면 상단의 S3 Object Lock: GOVERNANCE Mode (30 Days) 뱃지를 통해 규정 준수(Compliance) 상태를 확인합니다.
2
감사 로그 목록 필터링 및 검색
테이블에서 일시(Timestamp), 작업자(Principal), 작업 유형(CREATE / UPDATE / DELETE), 대상 SG ID를 확인합니다.
3
상세 변경 내역(Diff) 및 S3 원본 위치 열람
원하는 로그 행의 View Details 버튼을 클릭하면 모달 창이 열리며, 변경 전/후 규칙 JSON Diff와 S3 Object URI(s3Location)를 확인할 수 있습니다.

4. Backup Monitor (멀티 서비스 백업 관제)

EBS 볼륨, EFS 파일 시스템, RDS 데이터베이스의 일일 스냅샷 및 자동 백업 정책 준수 상태를 3대 탭으로 분류하여 실시간 감시합니다.

화면 캡처: Backup Monitor 멀티 서비스 백업 관제 대시보드 (#view-backup) Data Protection
EBS 볼륨, EFS 파일 시스템, RDS 인스턴스별 최근 스냅샷 시간과 백업 정책(Protected/Warning)을 확인합니다.

백업 관제 및 리소스 점검 사용법 (How-To)

1
상단 백업 요약 지표 확인
EBS Volumes Protected, EFS File Systems Protected, RDS Databases Protected 카드의 보호율(예: 100%)을 점검합니다.
2
서비스별 탭 전환 및 상세 리소스 점검
EBS Snapshots, EFS Backups, RDS Snapshots 탭을 클릭하여 각 스토리지 리소스의 연결된 인스턴스, 최근 스냅샷 생성 시간, 백업 플랜 태그를 검토합니다.
3
경고 리소스 조치
상태가 Unprotected 또는 Warning으로 표시된 리소스가 발견되면, 해당 리소스에 AWS Backup 태그를 부여하거나 즉시 스냅샷을 수동 생성합니다.

5. Slack 웹훅 알림 설정 (Notification > Slack)

다양한 운영 Slack 채널로 일일 백업 리포트 및 방화벽 변경 알림을 자동 전송하기 위해 다중 Incoming Webhook을 등록하고 관리합니다.

화면 캡처: Slack Webhook 다중 채널 설정 관리자 (#view-slack-webhook) Slack Integration
채널별 웹훅 URL, 메시지 포맷(detailed/simple), 발송 주기를 설정하고 실시간 테스트 발송을 수행할 수 있습니다.

Slack 웹훅 등록 및 테스트 사용법 (How-To)

1
신규 웹훅 추가 (+ Add Webhook)
1. 상단 + Add Webhook 버튼을 클릭하여 등록 모달을 호출합니다.
2. Webhook Name(예: #cloud-dev-alerts)과 Slack에서 발급받은 Incoming Webhook URL을 입력합니다.
3. Message Type(detailed: Block Kit 테이블 포맷 / simple: 컴팩트 텍스트)을 선택하고 저장합니다.
2
개별 웹훅 테스트 발송
목록에서 등록된 웹훅 행의 Test 버튼을 클릭합니다. 즉시 해당 슬랙 채널로 테스트 메시지가 성공적으로 전송되는지 확인합니다.
3
전체 웹훅 일괄 검증 (Test All Webhooks)
상단 Test All Webhooks 버튼을 클릭하면 등록된 모든 활성 채널로 일괄 테스트가 실행되어 통신 이상 유무를 한 번에 검증할 수 있습니다.

6. Email 주소 등록 & 일일 백업 리포트 (Notification > Email)

정기 일일 백업 요약 리포트를 수신할 담당자 이메일 목록을 관리하고, 완성된 HTML 이메일 보고서를 화면에서 직접 미리보기 및 즉시 발송합니다.

화면 캡처: Email 주소 관리 및 HTML 일일 백업 리포트 미리보기 (#view-email-recipients) Email & Report
담당자 이메일을 등록하고, 하단 미리보기 카드를 통해 실제 발송되는 HTML 리포트를 확인 및 즉시 전송할 수 있습니다.

이메일 수신자 등록 및 리포트 발송 사용법 (How-To)

1
이메일 수신자 등록
1. Add New Email Recipient 입력란에 수신할 담당자 이메일 주소를 기입합니다.
2. 쉼표(,), 세미콜론(;) 또는 줄바꿈으로 여러 주소를 동시에 입력할 수 있습니다.
3. + Add Recipient 또는 Save Recipients 버튼을 클릭하여 저장합니다.
2
HTML 일일 백업 리포트 미리보기 (Preview)
하단 Daily Backup Report Preview 영역에서 Preview Report 버튼을 클릭합니다. 현재 시점의 모든 AWS 계정 EBS/EFS/RDS 백업 상태가 집계된 실제 HTML 메일 테이블이 화면에 렌더링됩니다.
3
백업 리포트 즉시 발송 (Send Test Report Now)
우측 Send Test Report Now (또는 Send Email Now) 버튼을 클릭하면 등록된 모든 담당자에게 최신 백업 보고서가 즉시 이메일로 전송됩니다.

자주 묻는 질문 (FAQ) & 트러블슈팅

Q1. 로그인 시 "Failed to fetch" 오류가 발생합니다. API Gateway CORS 정책에 Access-Control-Allow-Credentials: true 설정이 적용되어 있으나, 브라우저가 이전 정적 캐시를 사용 중일 수 있습니다. 브라우저에서 Ctrl + F5(강력 새로고침)를 눌러 최신 스크립트를 로드해 주세요.
Q2. 8시간 후 화면을 클릭하니 "세션이 만료되었습니다" 알림이 발생합니다. BFF 보안 정책에 따라 발급된 HttpOnly 세션 쿠키는 8시간 TTL을 가집니다. 상단 헤더의 Re-login 버튼을 클릭하여 자격 증명을 입력하면 작업 상태를 유지한 채 세션이 갱신됩니다.
Q3. 특정 스포크 계정(예: l-ellotte-dev) 선택 시 보안 그룹 조회가 되지 않습니다. 해당 스포크 계정에 JungleToolsCrossAccountRole IAM 역할이 생성되어 있는지 확인하세요. 스포크 계정에서 spoke-account-template.yaml 템플릿을 배포하면 허브 계정의 STS AssumeRole이 정상 승인됩니다.
